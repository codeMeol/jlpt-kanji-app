# JLPT 한자 쓰기 구현·검증·출시 파이프라인

상태: 목표 구조(Target Architecture)  
패키지: `com.codemeol.jlptkanji`  
초기 출시 범위: N5, Android, 한국어 UI

## 1. 제품 목표

사용자는 한자 이미지만 먼저 보고 종이에 직접 써 본다. 카드를 누르면 읽기,
뜻, 획수와 설명이 열린다. 이전/다음 이동과 학습 상태는 Flutter가 담당하고,
카드 본문은 제한된 WebView가 표시한다. 관리자는 PenX에서만 콘텐츠를 만들고
수정한다.

### 첫 출시 포함 범위

- N5 학습용 추정 한자 103자
- 한자 이미지 한 장 우선 표시
- 탭하여 설명 표시/숨김
- 이전, 다음, 셔플
- 암기 완료 표시와 재실행 후 복원
- PenX 원격 콘텐츠
- 네트워크/PenX 장애 시 내장 데이터 fallback
- 출처 및 라이선스 고지

### 첫 출시 제외 범위

- 화면 필기 캔버스
- N4~N1
- 광고, 결제, 구독
- 사용자 계정과 클라우드 동기화
- AI가 생성한 한자 모양 또는 획순

## 2. 전체 구조

```text
KANJIDIC2
    │  원본 다운로드 + 해시 기록
    ▼
데이터 생성기(tool/generate_n5_data.mjs)
    │  정규화 + 한국어 훈음 + 스키마 검증
    ├──────────────► assets/data/n5.json (앱 내장 fallback)
    │
    ▼
PenX 관리자 API
    │  관리자 인증 → 초안 → 이미지 업로드 → 발행
    ▼
PenX 공개 JLPT 피드
    │  발행된 카드만 JSON 반환
    ▼
Flutter ContentService
    │  내장 데이터 즉시 표시 → 원격 갱신 → 검증 → 캐시
    ▼
Flutter 네이티브 셸
    │  현재 카드와 이동/암기 상태 관리
    ▼
제한된 WebView
       한자 이미지 → 탭 → 설명 표시
```

## 3. 책임 분리

### Flutter 네이티브 영역

- 앱 부팅과 오류 화면
- 카드 배열과 현재 인덱스
- 이전/다음/셔플
- 암기 상태 저장
- 네트워크 상태와 fallback 표시
- WebView 생명주기 관리
- 외부 URL 차단

### WebView 영역

- 현재 카드 한 장 렌더링
- 최초에는 한자 이미지 외 설명을 숨김
- 탭 시 설명 표시/숨김
- 페이지 이동, 인증, 로컬 저장을 담당하지 않음
- PenX 전체 페이지를 직접 열지 않음

### PenX 영역

- 관리자 콘텐츠 작성, 수정, 미리보기, 발행
- 이미지 저장과 공개 URL 제공
- 발행된 JLPT 카드 목록/상세 API
- 관리자 권한을 서버에서 검증
- 앱이 신뢰할 수 있는 구조화 메타데이터 반환

## 4. 데이터 수집 파이프라인

### 4.1 원본

- 주 출처: KANJIDIC2
- 라이선스: CC BY-SA 4.0
- 현재 JLPT는 급수별 완전한 한자 목록을 공개하지 않는다.
- N5 103자는 KANJIDIC2의 구 JLPT 4급 필드를 이용한 학습용 추정치다.

### 4.2 원본 보존

데이터 생성 시 다음을 기록한다.

- 다운로드 URL
- 다운로드 시각(UTC)
- 원본 SHA-256
- 라이선스 URL
- 생성기 버전
- 결과 데이터 SHA-256

원본 XML은 앱에 포함하지 않는다. 재생성 가능한 입력과 해시만 릴리스 기록에
남긴다.

### 4.3 정규화 스키마

```json
{
  "schemaVersion": 1,
  "cards": [
    {
      "id": "65E5",
      "kanji": "日",
      "level": "N5",
      "meaningKo": "날 일",
      "onReadings": ["ニチ", "ジツ"],
      "kunReadings": ["ひ", "-び", "-か"],
      "strokeCount": 4,
      "radicalNumber": 72,
      "frequency": 1,
      "sourceRefs": ["KANJIDIC2"]
    }
  ]
}
```

### 4.4 생성 검증

생성기는 실패 즉시 종료해야 한다.

- 카드 수가 정확히 103인지
- 한자가 한 글자인지
- ID가 유니코드 코드포인트와 일치하는지
- 한국어 뜻이 비어 있지 않은지
- 획수와 부수 번호가 유효 범위인지
- 중복 한자가 없는지
- 모든 항목에 출처가 있는지
- JSON 스키마 버전이 지원되는지

### 4.5 데이터 갱신

1. 새 KANJIDIC2 원본 다운로드
2. 해시 비교
3. 생성기 실행
4. 이전 JSON과 구조적 diff 생성
5. 한자 추가/삭제/읽기 변경을 사람이 검토
6. 승인된 diff만 커밋
7. 앱과 PenX 피드 양쪽에서 동일 데이터 버전 사용

자동으로 데이터를 바꾸거나 바로 배포하지 않는다.

## 5. PenX 게시 파이프라인

### 5.1 권한

- 생성/수정/삭제/초안 조회: `auth` + `requireAdmin`
- 공개 조회: `is_published = 1`인 JLPT 카드만
- 앱에서 관리자 토큰을 사용하지 않음
- 숨겨진 화면이나 프런트엔드 플래그로 권한을 대체하지 않음

### 5.2 카드 입력

관리자 입력값:

- kanji
- level
- meaningKo
- onReadings
- kunReadings
- strokeCount
- radicalNumber
- sortOrder
- 대표 이미지 한 장
- 상태(draft/published)

서버는 자유 형식 제목을 다시 파싱하지 않도록 구조화 메타데이터를 저장한다.
기존 `posts` 테이블을 사용하는 MVP에서는 본문에 버전이 있는 JSON 메타 블록을
저장하고, 전용 JLPT API가 이를 검증하여 반환한다. 장기적으로는 전용 테이블로
분리한다.

### 5.3 이미지 생성

한자의 자형은 AI로 생성하지 않는다.

- 승인된 일본어 서체로 결정론적으로 렌더링
- 정사각형 PNG 또는 WebP
- 옅은 전자격자/십자선
- 중앙에 검은 한자 한 글자
- 이미지 내부에 읽기나 뜻을 넣지 않음
- 동일 입력은 동일한 파일명과 결과를 생성
- 파일명 예: `n5-65e5-v1.webp`

### 5.4 초안과 발행

```text
관리자 입력
  → 서버 스키마 검증
  → 이미지 생성/업로드
  → draft 저장
  → 관리자 미리보기
  → publish
  → 공개 피드 반영
```

이미지 생성 실패 시 본문만 발행하지 않는다. 기존 발행본을 유지하고 오류를
관리자에게 반환한다.

### 5.5 공개 API 계약

```json
{
  "schemaVersion": 1,
  "datasetVersion": "2026-09-17.1",
  "cards": [
    {
      "id": "65E5",
      "postId": 1001,
      "kanji": "日",
      "level": "N5",
      "meaningKo": "날 일",
      "onReadings": ["ニチ", "ジツ"],
      "kunReadings": ["ひ"],
      "strokeCount": 4,
      "imageUrl": "https://meol.it.com/api/uploads/...",
      "updatedAt": "2026-09-17T00:00:00Z"
    }
  ]
}
```

응답에는 사용자 정보, 관리자 정보, JWT, 초안 콘텐츠를 넣지 않는다.

## 6. 앱 콘텐츠 동기화 파이프라인

### 6.1 부팅 순서

원격 요청 때문에 첫 화면이 지연되거나 앱이 종료되지 않도록 다음 순서를 고정한다.

1. Flutter 엔진 시작
2. 내장 `n5.json` 파싱
3. 네이티브 셸과 첫 카드 즉시 표시
4. SharedPreferences에서 인덱스와 암기 상태 복원
5. 백그라운드에서 PenX 피드 요청
6. HTTP 200, 스키마, 카드 수, 필수 필드를 검증
7. 검증 성공 시 메모리 데이터 교체
8. 마지막 정상 원격 피드를 로컬 캐시에 저장

원격 응답을 기다린 후 첫 화면을 만드는 방식은 사용하지 않는다.

### 6.2 데이터 우선순위

```text
검증된 최신 PenX 피드
    ↓ 실패
마지막으로 검증된 로컬 캐시
    ↓ 없음/손상
APK 내장 n5.json
```

어느 경우에도 빈 화면이나 강제 종료가 되어서는 안 된다.

### 6.3 원격 실패 처리

- DNS/타임아웃: 현재 데이터 유지
- HTTP 4xx/5xx: 현재 데이터 유지하고 조용히 기록
- JSON 파싱 실패: 응답 폐기
- 스키마 버전 불일치: 응답 폐기
- 이미지 404: 로컬에서 동일 한자를 렌더링
- 일부 카드 오류: 전체 원격 데이터셋을 적용하지 않음

## 7. 카드 렌더링 파이프라인

### 7.1 WebView 생성

- 화면당 WebView 하나를 재사용
- JavaScript는 로컬 카드의 설명 토글에만 사용
- 초기 HTML은 앱이 생성하며 원격 스크립트를 포함하지 않음
- PenX 본문은 HTML escape 또는 allowlist sanitizer 적용
- `https://meol.it.com` 이미지 외 원격 리소스 차단
- 링크 이동은 `NavigationDelegate`에서 전부 차단

### 7.2 카드 표시

1. Flutter가 현재 `KanjiCard` 선택
2. 카드 HTML 생성
3. 설명 영역을 `display:none`으로 시작
4. 한자 이미지만 표시
5. 사용자가 탭
6. 설명 영역 토글
7. 다음/이전 이동 시 설명을 다시 숨김

### 7.3 네이티브 이동

- 이전: 인덱스 -1, 처음이면 마지막 카드
- 다음: 인덱스 +1, 마지막이면 처음 카드
- 셔플: 현재 카드와 다른 인덱스 선택
- 암기: 카드 ID를 Set으로 저장
- 이동 직후 현재 인덱스를 저장

WebView 내부 URL 또는 브라우저 history로 카드를 이동하지 않는다.

## 8. 로컬 상태

SharedPreferences에는 다음만 저장한다.

- `last_card_index`
- `known_card_ids`
- `cached_dataset_version`
- 마지막 정상 원격 피드 캐시 키

개인정보, 광고 ID, 기기 ID, 로그인 토큰을 저장하지 않는다. 데이터셋 변경 후 없는
카드 ID는 정리하고 인덱스는 새 카드 수 범위로 보정한다.

## 9. 크래시 진단 파이프라인

현재 v1.0.0은 실패 빌드로 취급한다. 원인 확인 전에 UI, WebView, 테마, 서명을
동시에 바꾸지 않는다.

### 9.1 로그 확보

1. 물리 기기에서 개발자 옵션과 USB/무선 디버깅 활성화
2. ADB 연결 확인
3. 기존 로그 삭제
4. 앱 강제 종료
5. 로그 수집 시작
6. 앱 실행
7. `AndroidRuntime`, `FATAL EXCEPTION`, `flutter` 구간 저장
8. 예외 클래스, 첫 앱 코드 줄, 네이티브 라이브러리 확인

### 9.2 기능별 스모크 빌드

같은 패키지의 개발용 flavor 또는 feature flag로 하나씩 추가한다.

1. S0: MaterialApp + 정적 Text
2. S1: 내장 JSON 로드
3. S2: SharedPreferences 초기화
4. S3: 네이티브 카드 이동
5. S4: 빈 WebView 생성
6. S5: 로컬 카드 HTML 로드
7. S6: PenX 이미지/피드 연결

각 단계에서 설치, 콜드 스타트 5회, 60초 유지, 로그 확인을 마친 뒤 다음 기능을
추가한다. 최초 실패 단계가 원인 범위다.

### 9.3 진단 빌드 설정

- R8/minify 비활성화
- 디버그 심볼 보존
- 정확한 의존성 버전 고정
- 빌드마다 versionCode 증가
- APK 파일명에 버전과 Git SHA 포함

원인이 해결된 뒤에만 최소화를 다시 켜고 동일 검증을 반복한다.

업로드, 트랙 저장, 검토 제출, 승인/게시를 서로 다른 상태로 보고한다.

## 13. 스토어 준비

- 앱 전용 개인정보처리방침 URL
- 앱 전용 512x512 아이콘
- 앱 전용 1024x500 그래픽 이미지
- 실제 앱 화면 스크린샷
- 카테고리: 교육
- 광고: 없음
- 광고 ID: 사용 안 함
- 로그인: 필요 없음
- 데이터 보안: 로컬 학습 상태만 저장, 서버 전송 없음(현 설계 기준)
- KANJIDIC2 출처와 비공식 JLPT 분류 고지

Poker Club Manager의 개인정보처리방침이나 그래픽을 재사용하지 않는다.

## 14. 롤백

- PenX 데이터 오류: 원격 datasetVersion을 비활성화하고 앱은 캐시/내장 데이터 사용
- 이미지 오류: 이미지 URL을 제거하고 앱의 로컬 한자 렌더링 사용
- 앱 크래시: 문제 버전을 프로덕션으로 승격하지 않고 직전 내부 테스트 버전 유지
- 공개 후 중대 오류: Play 단계적 출시 중지, 수정 versionCode로 재배포
